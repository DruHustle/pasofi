# Backups

No production backup, off-server repository, archiving service or recovery scheduler is configured. A named local Docker volume is persistence, not a backup. Before production, implement encrypted off-server full-cluster backups and continuous WAL archiving, retention-aware expiration, isolated restore, reconciliation and old-server fencing. The proposed B2 and pgBackRest setup has not been configured or qualified.

`infra/backup-lab/run-lab.sh` is a disposable local recovery drill. It uses PostgreSQL 17, pgBackRest and a separate encrypted repository, then restores into an isolated cluster with all five service databases. It tests a transaction recovered from WAL after the full backup, a retained uncertain grant, a pending outbox event, duplicate-grant rejection and cross-service database isolation. It stops the old **test container** before starting the restored server; this does not prove external fencing of the Oracle VM. See the [lab README](../infra/backup-lab/README.md) for execution and limitations. No live customer data or external destination is used.
