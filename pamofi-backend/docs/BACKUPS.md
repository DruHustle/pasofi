# Backups and independent recovery

The repository now contains an optional [production pgBackRest/B2 overlay](../infra/backup-production/README.md): a separate encrypted repository, continuous WAL archiving, protected credentials, retention commands and an explicit restore/fencing procedure. It has not created a B2 bucket, enabled archiving on a live database, scheduled host jobs or established off-host recovery. A named Docker volume provides persistence only.

The production overlay is intended to protect the complete PostgreSQL cluster, including all five service databases, role boundaries, migration history, balances/reservations and outbox state. Its protected input files and repository identifiers must be supplied by the operator. Activation preserves the existing PGDATA/volume, requires a reviewed database restart, and must be followed by real stanza creation, backup, archive and restore evidence. Key custody, retention capacity, alert delivery and a recovery copy independent of the application host remain qualification work.

The [disposable backup lab](../infra/backup-lab/README.md) uses PostgreSQL 17, pgBackRest and a separate encrypted repository. It restores all five databases into an isolated cluster, exercises wrong-key rejection and a transaction recovered from WAL after the full backup, retains an uncertain grant and pending outbox event, and checks duplicate-grant refusal and cross-service isolation. Stopping the old test container proves the laboratory sequence; it does not fence an Oracle VM or prove access to an external B2 account.

Before serving customers, schedule and monitor backups/WAL checks, restore on a different host with independently retained keys, fence the old authority, reconcile pre-restore live grants and provider references, and record measured recovery point/time. Never restore over the active cluster or run two grant authorities. Follow the production overlay's procedure and [current build status](BUILD_STATUS.md); source configuration or a local lab pass is not a running backup service.

The [read-only operations checker](../infra/operations/README.md) can detect a failed repository status or stale completed backup. Its result complements scheduled WAL checks and restore drills; it does not prove continuous archiving or off-host key recovery by itself.
