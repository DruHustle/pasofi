### Security follow-up after that run

Independent review found a concrete UI race: a delayed initial/refresh staff session response, or the GET after MFA confirmation, could restore a cleared prior staff view after another tab signed out. Challenge expiry also left an old challenge owner in memory. `StaffWorkspace.tsx` now guards every async action with an invalidatable generation; broadcast, expiry, logout and unmount invalidate prior state updates and finally handlers. Expiry clears the challenge owner and secret. Failed DELETE still preserves the current authenticated view rather than claiming sign-out.

Two held-response Chromium regressions now release the old initial or post-MFA GET only after a cross-tab sign-out. Both confirm that neither staff access nor the authenticator setup key reappears. The complete workspace suite passed 11/11 and the web production build passed. The next full strict result must include these two cases and additional backend regression changes before final acceptance of that later source revision.

### Retry-flow follow-up and final source freeze

Two concrete form locks were corrected after the 126-test run. An expired unused checkout previously retained its intent forever. The new authenticated `POST /v1/orders/:id/expire-unused` uses the same order lock as payment initiation and requires server-clock expiry with no attempts, charges or entitlements. Only a matching, durable `expired_unused` response with `safeToRequote: true` lets either customer frontend discard the old intent. A lost closure response safely retries the same owned order; any provider attempt preserves the purchase identity.

An agent's definitive pairing/stock rejection also previously froze its sale form. Only five serialized, rolled-back voucher-domain errors now release that draft. Early site/SMS gateway rejections, idempotency conflicts, delivery uncertainty and lost/5xx responses preserve the original retry key because an in-flight sale could still commit.

The complete web workspace suite passed **13/13** after these fixes, including the two staff race regressions, safe requote with a lost closure reply, and distinct handling of rolled-back sale errors versus ambiguous gateway rejection. The complete mobile suite passed **7/7**, including refusal to discard a quote with an existing provider attempt. Both frontend production builds and Git whitespace checks passed. The final web source contains 33 browser cases overall; these focused results must not be added to the historical 126 count and called a new complete run. The final strict CI run records its own totals for the exact published source.
